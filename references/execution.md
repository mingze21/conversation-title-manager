# 执行与断点

## 资格与标题

读取当前用户确认的配置和两个平台独立状态。检查 enabled、启用时间、基线、排除 ID、逐项记录及本轮授权。管理会话、内部子代理／审核记录排除。状态字典和列表两种旧结构都先识别再读取，不能假定 `records` 结构一致。

选择模式：只读预览、执行当前明确范围、每日新增、恢复已授权冻结批次。用户本轮要求预览时即使有旧自动授权也只做预览。定时每个分支在一个计划窗口最多完成一次；不能固定用“每日一次”限制用户选择的多时段计划。两个平台的检查状态独立；网页每日新增和历史恢复共用一次访问检查及停止条件。

新增同时满足：ID 不在基线／排除／永久保护中，真实 createdAt 晚于该平台 enabledAtUtc。晚发现不是晚创建。冻结批次只处理授权集合和未完成交集；基线并非冻结授权失效理由。用户外改保护、已成功、归档及不合适运行状态依然有效。

明确记录标题来源 unknown。只有本用户授权允许首次未知来源统一命名，才可执行；已经观察到外部标题变化、存在明确人工命名证据或已自动命名成功的保留。旧保护标记只记录过时原因时，结合仍有效的特定授权和新的证据判断，不能机械认定用户撤销授权，也不能抹除其他保护。

主题依据实际内容和用户最终确认目标；优先最后确定范围，而非临时插问。每条只选一个配置中的类别；报告只是载体时不自动归文档，改错与改善效果区分，技能本身才归 Skill。无法可靠判定时保留。现有准确合规标题不改。

日期必须追溯字段、来源与时区。通常从宿主 `read_thread` 核实；已明确允许的历史批次可复用原预览中同一 ID 的可信 createdAt，记录源文件、字段、原核实时间，标 `freshCreatedAtRetrieved=false`。旧时间证据不能代替当前标题、内容和状态核实。未得到此例外授权，不擅自放宽新会话的当前日期核验。

## Codex 路径

- 使用官方 `list_projects/list_threads/list_archived_threads/read_thread/set_thread_title` 等现有能力。需要补齐本机范围时，可只读实际索引；SQLite 必须 `mode=ro` 及 `PRAGMA query_only=ON`，不直接写数据库、缓存、安装文件。
- 最新服务端状态必须明确 `notLoaded` 且未归档，`idle` 不等价；不可为检查停止、关闭或卸载会话。独立读取工具会影响加载状态时，之后重验，不操作卸载来满足条件。
- 核实当前改名路径可保持真实创建时间、正文、项目／分组、置顶、归档。优先当前版本已有的正式实改证据。升级仅触发相关路径的只读核实，不必因版本变动无依据地全局阻挡；静态核查不是所有目标的成功保证。
- 保存目标级保护快照；只有有具体异常才暂缓对应项。遇到真实保护变化或不明写入停止相关批次，不为“测试兼容性”改一个范围外真实会话。
- 提交前核对原名，使用 `set_thread_title` 逐条改名，立刻回读标题和保护字段。正文核验可用完整内容指纹；正常读取将 `.jsonl.zst` 恢复成 `.jsonl` 时比较解压内容或等价指纹，不能只凭路径变化认定正文变了。记录实际核验范围，不夸大。

## ChatGPT 网页路径

- 只使用用户已授权的浏览器正常界面发现会话、检查状态和“重命名”；应用 `read_thread` 核实真实创建时间和必要内容。使用浏览器工具当前文档，不复制旧元素编号。
- 不请求需认证网页 API，不提取 Cookie／令牌，不切账号、自动登录、安装连接器或扩大权限。网页不能用本地 Codex 的 `notLoaded` 门槛；应检查同一目标 ID、原名、未生成状态、项目／置顶／归档。
- 项目字段缺失要记 unknown，不能推成无项目。只有当前用户对具体范围确认“按正常重命名与前后可见状态核验，项目字段缺失不单独阻止”时应用例外。已有明确字段冲突不在例外内；此例外不随 Skill 分发转给新用户。
- 已归档会话不取消归档处理。网页操作与应用内容读取串行；最小改名间隔 10 秒。先保存提交中记录再点击保存，UI 回读并核验已知保护状态，必要时官方回读交叉核对。旧缓存标题不构成再点保存的依据。
- 访问、搜索、登录或服务出错时保留具体可见错误并结束本轮网页分支；未见限流提示不能称为限流。超时或提交结果不明时只读核验，无法确认则 `verification_pending` 并停止，不重复提交。下一计划窗口先轻量检查恢复；同一窗口无恢复证据不循环刷新或重试。另一个平台继续独立工作。

## 可恢复日志

不要把用户数据存在 Skill 包内。每平台维护实际启用时间、基线和排除 ID、最新计划窗口结果；每个范围固定独立运行记录。修改用单写入者或明确分工避免覆盖；写入前核对当前文件，备份后用同目录临时文件和原子替换，读回校验。两个平台状态分别保存，不用一个“今日完成”停止全部任务。

每条至少保存：平台、会话 ID、scope/authorizationRef、原名、拟定／执行名、真实 createdAt 及单位来源、时区日期、主题与分类简短依据、标题来源、已知保护状态、unknown 字段、提交时间、回读结果及具体跳过原因。只存摘要和指纹，不存凭证或全文。

建议状态：`candidate`、`ready`、`submitted`、`verification_pending`、`renamed`、`unchanged`、`deferred`、`protected_external_change`。`renamed` 只能在实际提交和核验通过后写入；候选、预览、命令返回成功都不能代替它。未知结果的恢复先查是否已生效。成功永久跳过；外改永久保护，除非新的具体授权改变它。

报告按平台列实际改名、无需修改、暂缓／跳过、失败、未检查，另列总覆盖未知。历史目标已检查却无法定位，仍是未改，不从“未处理”计数里消失。只有全部授权对象均已结清才称批次完成；检查完成不等于全部标题已改。

遵守宿主 heartbeat 输出格式；没有实际变化或新的行动项时保持安静。仅在缺失关键条件需要用户介入时提具体问题，不把每天的同一访问失败当新待办。
