# 已有任务接续

本参考只用于用户已有命名规则、自动任务和日志时。安装新 Skill 不重新初始化基线、启用时间或授权，不因当前目录和安装者不同继承原作者的账号范围。

1. 从当前用户明确路径或个人配置 `legacyAdapter` 查找旧规则、两个平台状态、原自动任务 ID 和必要授权清单。确认属于当前任务／账号；只读检查字段与日志结构。
2. 建一个个人适配配置，引用这些源文件，不复制动态 ID、授权正文和执行状态进 Skill。旧规则版本不等于 Skill 版本；迁移首次使用版应记录“无前版／初次创建”，来源规则另列。
3. 当前任务和本用户仍有效授权是依据。规则文件的通用约束与之后批准的具体例外冲突时，采用范围匹配的较新明确授权；冻结 ID、指纹、scope 和实际执行结果逐项核对，不用聚合数量替代成员集合。
4. 最新正式实改证据优先于旧镜像运行版本字段。禁止因陈旧兼容标记永久跳过全部，也不能把某些成功扩成无限制执行。
5. 已存在定时任务保持当前时间、时区、目标会话和通知偏好。用户要求接入 Skill 或修改调度时用宿主正式更新工具，先保存原配置，完整保留未请求变更字段；不自动重建第二个任务。
6. 旧执行脚本可能带固定日期、作者路径、字段假设或授权集合，不直接复制成通用执行器。移植工具只做确定性的本地格式校验；平台写入仍交给正式工具／正常界面。

适配器建议只存路径和模式，例如 `codex.ruleFile/stateFile`、`web.ruleFile/stateFile`、`authorizationFiles`、`historicalExecutionFiles`、`automationId`。具体 ID 集合从源文件读取且验证，缺文件时不猜测或重建授权。

个人配置或已批准的调度提示词可以包含本机绝对路径；可分发 Skill 不预填 E 盘、管理会话 ID、作者姓名、固定分类或固定运行时间。打包前排除个人配置、扫描结果、浏览记录和执行日志。
